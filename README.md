## Структура бэкэнда проекта
Проект парсит список 100 лучших вузов планеты **по критерию QS**, затем переходит на 100 страниц с информацией об этих вузах и парсит оттуда другие параметры вузов **(количество Undergrad. & Postgrad. Programmes).**  
Вся логика **парсинга** реализована в **backend/parsing.py** в виде функций.  
Все эти данные передаются в таблицу sqlite3, вся логика **работы с БД** реализована в **backend/databasecode.py** в виде функций.  

Файл **backend/app.py** является главным, поднимает flask, обрабатывает события на клиенте, использует функции из других файлов для выполнения задач.

Фронтенд представляет из себя index.html и добавить тут нечего. Остальные файлы проекта используются для работы докера, db, зависимостей и пр.

## Как запустить?
1. откройте git bash
2. клонируйте проект
3. проверьте наличие и целостность файлов
4. chmod +x build.sh
5. запустите Docker Desktop
6. используйте ./build.sh для автоматической сборки (после сборки покажет на каком порте доступен сервис)
7. Перейдите на указанный порт в браузере
8. используйте docker-compose down для остановки

sortqs - производит сортировку данных по параметру **(количество Undergrad. & Postgrad. Programmes).** в порядке убывания.  

## Основные реализованные сложности/преимущества
1. парсинг данных с сотни страниц, чьи адресы были спаршены до этого, без использования БД
2. парсинг (и вообще всё в проекте) обернуто try except, особенно парсинг, потому что на сайтах посвященных разным вузам оказалась разная структура, иногда типы данных (или полное отсутствие данных - None, что было приведено к 0)
3. реальный функционал сервера app.py разведен с функционалом скрапинга и функциями для работы с базой данных  
4. переменная хранящая количество записей в БД сохраняет своё значение между сеансами  

### Не реализованное/удаленное
1. Парсинг других параметров вуза (сайты не приведены к общей структуре и потому написание общего селектора + приведение к одному типов данных оказалось слишком сложным.)    
2. Из-за этого пришлось удалить сортировки по другим значением в app.py (которые в прочем отличаются в реализации 2 или тремя символами)  
3. Темная тема клиента  
4. Консольная версия ввода команд/получения ответов от сервера.
